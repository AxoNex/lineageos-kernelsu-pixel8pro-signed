# 07 · 常见问题（FAQ）

## Q1：回锁后无法开机，显示「Your device is corrupt」怎么办？
软砖。前提是回锁前开启了「OEM 解锁」，否则无法自救：
```bash
fastboot flashing unlock   # 清空用户数据后恢复解锁
```
之后排查：`WITH_AVB := true` 是否真的生效、`avb_custom_key.bin` 是否与签名用的 `avb.pk8` 配对、所有分区（含 `pvmfw`）是否均已自签名。

## Q2：能否换签名密钥？
已发布后再换密钥会破坏既有设备的升级/回锁。需走密钥迁移（见官方文档「Changing keys」）。因此密钥应一次性生成并长期保存。

## Q3：`check_keys.py` 报某些包签名不一致？
LineageOS 官方说明：个别目标（如 `com.android.apex.cts.shim.v1_prebuilt`）本就应使用其他密钥，属预期。

## Q4：找不到 `avb_custom_key.bin`？
只有 template 模式会生成它。manual 模式需自行用 `avbtool extract_public_key` 从 AVB 私钥导出。

## Q5：线刷时动态分区报错？
确认已进入 fastbootd（`fastboot reboot fastboot`），且 `super_empty.img` 存在。逻辑分区必须在 fastbootd 下刷写。

## Q6：系统更新里看不到自定义源？
- 确认属性 `lineage.updater.uri` 已写入设备 tree 并重新构建、刷入；
- 核对属性名（`grep -rn "updater.uri" packages/apps/Updater`）；
- 确认 `updates.json` 的 `url` 与 `OTA_DOWNLOAD_BASE` 匹配、服务端可访问。

## Q7：blu_spark 内核分支选哪个？
需与所用 LineageOS 内核版本线一致（Pixel 8 Pro = Tensor G3 / zuma）。参考 `engstk/gs` 仓库 README 与你的 LineageOS 版本对应关系，不确定时先在解锁状态下单刷内核 zip 验证。

## Q8：OTA 安装失败？
- 确认 OTA 用 `releasekey` 签名，且设备当前安装的构建使用同一套密钥；
- 跨密钥升级需先做密钥迁移（Q2）；
- 回锁设备要求 OTA 的 vbmeta 签名与已刷入的信任根一致。

## Q9：本工具能直接在 Windows 上跑吗？
制作脚本（`scripts/`）需在 **Linux 构建机**上运行（依赖 LineageOS 构建环境与 `bash`）。Windows 上只需用 `windows/flash-all.bat` 做线刷。
