# 02 · 首次配置

一次性配置，完成后即可全自动构建发布。

## 步骤 1：推送仓库

把本目录推到 GitHub（仓库名全小写、定名后别改——设备端 `lineage.updater.uri`
会写死 `https://<owner>.github.io/<repo>/updates.json` 地址）。

## 步骤 2：生成签名密钥

1. 打开仓库 → **Actions** → 左侧选 **「Init Signing Keys」** → **Run workflow**。
2. （可选）在 `passphrase` 输入框填一个口令；留空则密钥明文。
3. 运行完成后，点开本次运行 → 展开「生成密钥并打印 SIGNING_KEYS」步骤，
   复制 `SIGNING_KEYS 开始/结束` 之间的一整段 base64。
4. 前往 **Settings → Secrets and variables → Actions → New repository secret**：
   - Name = `SIGNING_KEYS`，Value = 刚才复制的 base64。
   - 若步骤 2 填了口令：再建一个 Secret `KEY_PASSPHRASE` = 该口令。

> ⚠️ **密钥必须长期保留**：丢失 = 无法给后续 OTA 签名 = 必须解锁 + 清数据 + 换新钥。

## 步骤 3：启用 GitHub Pages

1. **Settings → Pages** → Source 选 **「GitHub Actions」**。
   （否则构建最后一步 deploy-pages 会报 "Pages site not configured"。）
2. 无需其他配置；首次部署后 `https://<owner>.github.io/<repo>/updates.json` 即可访问。

## 步骤 4：首次触发构建

1. **Actions → Build & Release → Run workflow**（可勾选 `force` 强制构建）。
2. 构建完成会自动：
   - 发布 Release（`<版本>-fastboot.zip`、`<版本>-ota.zip`、`avb_pkmd.bin`）；
   - 部署 `updates.json` 到 Pages。
3. 下载线刷包，按 [04-线刷与回锁](04-线刷与回锁.md) 刷入设备。

## 步骤 5：配置定期检测

`build-release.yml` 已内置 cron（默认每周日 02:00 UTC）。如需改频率，编辑：

```yaml
on:
  schedule:
    - cron: '0 2 * * 0'   # 分 时 日 月 周（UTC）
```

LineageOS husky nightly 通常每日发布，可改为 `'0 2 * * *'`（每天 02:00 UTC）。
