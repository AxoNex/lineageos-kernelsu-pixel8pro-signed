# 03 · 密钥生成与自签名

## 方式一：官方模板（推荐，脚本默认）

LineageOS 提供 `lineage/scripts/lineage-priv-template`，其 `keys.sh` 一次性生成全部所需密钥，**包括**：

- 通用密钥：`platform`、`releasekey`、`media`、`shared`、`networkstack`、`bluetooth`、`verity` 等
- 全部 APEX 密钥
- **AVB 密钥**：`avb.pk8`（私钥）+ `avb_custom_key.bin`（公钥，硬件信任根）

脚本 `00-init-keys.sh` 会自动执行：

```bash
mkdir -p vendor/lineage-priv
cp -r lineage/scripts/lineage-priv-template vendor/lineage-priv/keys
cd vendor/lineage-priv/keys && ./keys.sh
```

生成后，构建时会**自动套用**这些密钥（无需再手动签名 target-files）。

## 方式二：手工生成（脚本仅给指引）

见 [LineageOS 官方签名文档](https://wiki.lineageos.org/signing_builds.html)，核心命令：

```bash
subject='/C=US/ST=California/L=Mountain View/O=Android/OU=Android/CN=Android/[email protected]'
mkdir -p ~/.android-certs
for cert in bluetooth cyngn-app media networkstack nfc platform releasekey sdk_sandbox shared testcert verity; do
  ./development/tools/make_key ~/.android-certs/$cert "$subject"
done
```

APEX 密钥需把 `make_key` 的 RSA 位数由 2048 改为 4096 后逐个生成（数量极多），**强烈建议用方式一**。

## 全量自签名

### 模板模式（自动）
构建产物（APK / APEX / 镜像 / vbmeta）在 `mka target-files-package` 时已用你的密钥签名完成。脚本会可选地运行 `check_keys.py` 校验。

### 手工模式（需手动签名）
```bash
sign_target_files_apks -o -d ~/.android-certs \
    --extra_apks ... --extra_apex_payload_key ... \
    target_files.zip signed-target_files.zip
```
其中 `--extra_apks` / `--extra_apex_payload_key` 列表很长且随 LineageOS 版本变化，完整命令见官方文档「Generating an install package」章节。

## 密钥安全

- `keys.sh` 生成的密钥**无密码保护**：请离线备份 `vendor/lineage-priv/keys`，并限制其访问权限。
- **`avb.pk8` 私钥丢失 = 无法再签发与已刷入公钥匹配的镜像 = 设备无法正常 OTA 更新**（尤其回锁后）。务必妥善保存。
- 密钥一旦用于发布，不要更换；更换需走密钥迁移（见官方文档「Changing keys」）。
