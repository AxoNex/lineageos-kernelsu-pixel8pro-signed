# 03 · 工作原理（重打包流水线）

`scripts/make_all.sh` 依次执行以下步骤（可单独运行任一步骤）。

## 00 · 检测上游新版本

查询 `https://download.lineageos.org/api/v2/devices/husky/builds`（裸 JSON 数组），
取最新构建的 `version` / `datetime` / `files[0]`（OTA 的 filename/url/sha256/size）。
与已发布的 GitHub Release 比对：版本已存在则跳过（`SHOULD_BUILD=false`），
否则写 `upstream.env` 并继续。`FORCE_BUILD=true` 时忽略「已发布」检测。

## 01 · 下载

- **avbroot v3.39.1**：从 GitHub Release 下载 x86_64 二进制，sha256 校验。
- **官方 OTA**：从 LineageOS v2 API 的 url 下载，sha256 校验（约 1.4GiB）。
- **blu_spark boot**：查 `engstk/gs/releases/latest`，用正则匹配
  `blu_spark_gs-los-v*.img`（非 `-next`）作为 boot 镜像。`gs-los` = LineageOS 专用。

## 02 · 恢复密钥

从 Secret `SIGNING_KEYS`（base64 tar）解出 4 个文件到 `$KEYS_DIR`：

| 文件 | 用途 | 对应 AOSP 密钥 |
|------|------|----------------|
| `avb.key` | 签 vbmeta / 分区 hashtree | avb.pem |
| `ota.key` | 签 OTA payload | releasekey.pk8 |
| `ota.crt` | OTA 自签证书 | releasekey.x509.pem |
| `avb_pkmd.bin` | bootloader 信任根公钥 | avb_pkmd.bin |

## 03 · 修改 product 分区（自定义更新源）

官方构建的 `lineage.updater.uri` **未设置**（更新器回退到内置
`download.lineageos.org` 官方源）。本步骤把它指向自定义服务器：

```
avbroot ota extract -p product      # 解出 product.img
avbroot avb unpack -i product.img   # → avb.toml + raw.img（裸 ext4）
debugfs -w 改 /build.prop           # 追加 lineage.updater.uri=https://...
avbroot avb pack -o product.new.img -k avb.key --recompute-size
```

关键点：

- `product` 分区是 **ext4**（非 erofs），用 `debugfs` 直接改，无需挂载/root。
- `build.prop` 允许存放非 `ro.` 属性，`lineage.updater.uri` 可被
  `SystemProperties.get()` 读取。
- `--recompute-size` 仅用于可缩放分区（system/product），重建 hashtree 并重签。

## 04 · avbroot 重打包 + 签名

```
avbroot ota patch \
  -i 官方ota.zip -o <版本>-ota.zip \
  --key-avb avb.key --key-ota ota.key --cert-ota ota.crt \
  --prepatched blu_spark_boot.img \
  --replace product product.new.img
```

avbroot 在此完成：

1. 用 `--prepatched` 替换 boot 为 blu_spark 内核（校验兼容性）；
2. 用 `--replace` 替换 product 为改过属性的分区；
3. 替换 system / recovery（boot/vendor_boot）内 `otacerts.zip` 为自定义 OTA 证书；
4. 重签被改分区 + 重建 vbmeta 信任链（保证回锁后能通过校验）。

最后 `ota verify --cert-ota ota.crt --public-key-avb avb_pkmd.bin` 校验产物签名。

## 05 · 线刷包 + updates.json

- `avbroot ota extract --fastboot`：解出可线刷镜像，并生成
  `android-info.txt`（require board=husky）与 `fastboot-info.txt`
  （静态分区 → `reboot fastboot` → 动态分区 → wipe 序列），`fastboot flashall` 直接用。
- 打包 `<版本>-fastboot.zip`，并附 `avb_pkmd.bin`。
- 调 `gen-updates-json.py` 生成 `updates.json`（见 [05-OTA与自定义更新源](05-OTA与自定义更新源.md)）。

## 06 · 发布

- `gh release create`（或 upload 到已存在 release）：上传 OTA + 线刷包 + 信任根公钥。
- 工作流另用 `upload-pages-artifact` + `deploy-pages` 把 `updates.json` 部署到 Pages。

> 注：OTA 文件本体放 **Releases**（≤2GB 上限，1.4GiB 满足）；`updates.json` 放
> **Pages**（直连 200，满足更新器不跟随重定向的要求）。
