# 06 · 常见问题

### Q1：为什么要用「重打包」而不是「源码构建」？
完整 LineageOS 源码构建需 ~250GB 磁盘 / 32GB 内存，免费 runner（14GB 盘 /
7GB 内存 / 6h）跑不动。重打包只做解压/改文本/重打包/签名，免费 runner 即可。

### Q2：免费版 GitHub runner 真的够吗？
够。本流程峰值约 5~8GB 磁盘（1.4GiB OTA + 解包中间产物）、约 2~3GB 内存，
远低于 ubuntu-latest 的 14GB/7GB 上限。

### Q3：更新器报 "Unexpected HTTP status: 302"？
`updates.json` 的 URL 用了会 302 的地址（如 `releases/latest/download`）。
改用 GitHub Pages（直连 200），见 [05](05-OTA与自定义更新源.md)。

### Q4：更新器提示无法验证 OTA / 校验失败？
检查 `updates.json` 里 `sha256` 是否等于 OTA zip 真实值（`gen-updates-json.py`
会自动算，手工改时易错）。另外确认 `otacerts.zip` 已被 avbroot 替换为你的证书。

### Q5：回锁后进不了系统（卡 bootloader）？
通常是**没先烧 `avb_custom_key`** 就锁了，或用错密钥签名。解锁后重来：
`fastboot flashing unlock` → 确认烧入 `avb_pkmd.bin` → 重刷 → 再锁。

### Q6：blu_spark 内核不兼容，构建报 "prepatched boot image is not compatible"？
avbroot 的 `PrepatchedImagePatcher` 会校验 KMI（内核模块接口版本）。报这个错
说明 blu_spark 分支与当前 LineageOS 版本线的 KMI 不一致。确认用的是 `gs-los`
（LineageOS 专用）分支，且版本线与 LineageOS 匹配（如 A17 ↔ blu_spark-17-los）。
脚本会自动匹配最新 `gs-los` 资产，一般无需干预。

### Q7：多久触发一次构建？
默认 cron 每周日 02:00 UTC（`build-release.yml` 可改）。检测到上游有新版本才
构建发布；无新版直接跳过。

### Q8：密钥丢了怎么办？
无法签后续 OTA。只能 `fastboot flashing unlock`（清数据）→ 烧官方固件 →
运行「Init Signing Keys」换新钥 → 重刷。**务必妥善保存 `SIGNING_KEYS`**。

### Q9：能同时支持多个设备吗？
当前硬编码 husky。加设备需改 `DEVICE_CODENAME` 并确认 avbroot 支持该设备
（见 avbroot issue #299 的支持列表）与 blu_spark 是否有对应镜像。

### Q10：仓库必须 public 吗？
启用免费 GitHub Pages 需要仓库 public。private 仓库无 Pages（免费账户）。
若必须 private，可改用自建服务器托管 `updates.json`。
